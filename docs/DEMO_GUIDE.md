# 3–5 minute judge demo

All names and sample data are fictional. Use one browser and the profile switcher; changes persist in that browser's local storage.

1. **0:00–0:40 — Problem and catalogue.** Open the dashboard. Explain that campus equipment can be idle while teams need it. Explore resources and search for “camera”; open details to show location, use, restrictions, supervision and eligibility.
2. **0:40–1:30 — Student request.** Request the DSLR. Enter a project purpose and a future 1–2 hour window, then submit. Point out the pending state, staff review and FairShare cap.
3. **1:30–2:20 — Trustworthy approval.** Switch to Resource staff, open Approvals and approve with an explanation. Switch back to Student and show the request status. If demoing schedule safety, submit a second overlapping DSLR request before approval and show the transparent waitlist.
4. **2:20–3:20 — Handover and return.** On the student booking, record checkout with an initial condition note, then record return with final condition notes. Point out that both are in the activity trail.
5. **3:20–4:20 — Operations and trust.** Switch to staff, show resource management, add or deactivate a fictional listing, then report and resolve an incident. Show the audit history as staff/admin and explain that this is a local demo trail, not tamper-proof backend persistence.
6. **4:20–5:00 — Close.** Explain that SQL migration defines intended Supabase RLS and overlap constraints, while hosted authentication/database integration is still a manual engineering step.
